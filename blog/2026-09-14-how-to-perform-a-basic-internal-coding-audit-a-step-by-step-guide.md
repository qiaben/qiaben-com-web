A coding audit is a practical way for a healthcare practice to check whether the codes reported on claims are supported by the medical record. A basic internal audit does not need to be complicated. With a small sample of records and a consistent review process, practices can identify coding errors, documentation gaps, and areas that need improvement.

Regular reviews can also help coding teams maintain accuracy and catch recurring problems before they affect a larger number of claims.

![How to Perform a Basic Internal Coding Audit](/img/uploads/2026/09/how-to-perform-a-basic-internal-coding-audit.png)

## 1. Define the Purpose of the Audit

Before reviewing any records, decide what you want the audit to check. For a basic audit, the focus might be accurate code selection, documentation support, correct use of modifiers, or common coding errors. Keeping the scope specific makes the review easier and helps the team produce useful results.

You should also decide which provider, service type, payer, or time period will be reviewed.

## 2. Select a Small Sample of Records

You do not need to review hundreds of charts for a basic internal audit. Start with a manageable sample that represents the area you want to examine.

Try to select records randomly rather than choosing only easy or successful cases. A random sample can provide a more realistic picture of the coding process.

CMS guidance on self-auditing recommends using a defined sample of records and notes that practices can start with a small audit rather than allowing sample size to prevent them from beginning the process.

## 3. Compare the Codes With the Documentation

This is the most important part of the audit.

Review the medical record and compare it with the codes submitted on the claim. Ask whether the documentation supports the reported service and whether the selected code accurately represents what was performed.

Check the diagnosis, procedure, service level, date of service, and other relevant details. CMS advises that documentation in the medical record should support the CPT, HCPCS, and ICD-10-CM codes reported on a claim. If the record does not support the code, document the issue rather than assuming the code is correct.

## 4. Check CPT Code Selection

Next, review whether the correct CPT code was selected for the documented service.

Look for issues such as:

- Choosing a code that does not match the documented procedure
- Using an outdated code
- Selecting an incorrect level of service
- Missing a required modifier
- Reporting codes that should not be billed together

The goal is not simply to check whether a five-digit code appears on the claim. The code should accurately describe the service documented in the patient's record.

## 5. Review Modifiers and Code Relationships

Modifiers can provide additional information about how or why a service was performed. During the audit, check whether modifiers were used when appropriate and whether they are supported by the documentation.

Also look for coding combinations that may create billing issues. For Medicare claims, CMS's National Correct Coding Initiative includes procedure-to-procedure edits designed to prevent incorrect code combinations.

Do not add or remove a modifier simply to change reimbursement. The documentation should support the coding decision.

## 6. Check for Upcoding and Undercoding

Review whether the level of service reported matches the actual documentation.

Upcoding occurs when a higher-level service is reported than the documentation supports. Undercoding occurs when the reported code does not fully represent the documented service.

Both can create problems. The purpose of an internal audit is to identify these patterns and understand why they are occurring. If several records show the same issue, the practice may need additional education, clearer coding procedures, or a review of its workflow.

## 7. Record and Categorize the Findings

Do not simply mark a claim as correct or incorrect. Record what was wrong and why.

For example, findings might include:

- **Documentation issue:** Required information was missing.
- **Code selection issue:** The selected CPT code did not match the documented service.
- **Modifier issue:** A modifier was missing or unsupported.
- **Process issue:** The same coding mistake appeared across multiple records.

Keeping findings organized makes it easier to identify patterns and determine which problems require attention first.

## 8. Take Corrective Action

An audit has little value if the findings are never addressed. If you discover an isolated mistake, correct it according to your organization's procedures. If the same issue appears repeatedly, investigate the reason behind it.

The solution might involve coder education, updated internal guidelines, better documentation practices, or additional review before claims are submitted. CMS recommends using self-audit results to identify common documentation, coding, and billing problems, followed by corrective action and education.

## 9. Recheck the Problem Area

After corrective action has been taken, perform another small review.

For example, if an audit found repeated modifier errors, review a new sample after staff training. If the same issue continues, the practice may need to examine the process more closely.

## Final Thoughts

A basic coding audit does not have to be difficult. Start with a clear purpose, select a manageable sample, compare codes with documentation, review CPT selection and modifiers, and record your findings.

The most important step is to use the results for improvement. Consistent internal reviews can help coding teams identify recurring problems and maintain more accurate claims.
